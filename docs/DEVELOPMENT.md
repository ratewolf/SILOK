# 구현 계획과 협업

## 현재 기반

XML → SQLite → Text-to-SQL → 제한된 읽기 전용 조회까지 CLI가 있다. Gradio GUI는 아직 없다. 패키지명 `sillok_poc`와 `data/sillok_poc.db`는 기존 명령을 유지하며, 이름 변경은 별도 작업으로 진행한다.

현재 스키마는 `records(article_id, reign, year, date_raw, title_ko, original_text, categories)`다. `year`는 원문 서기 연도이며 재위 연도가 아니다. `date_raw`의 윤달 표기를 보존한다. 한국어 제목·분류 검색과 한문 본문 의미 검색을 구분한다.

## 단계별 완료 기준

1. **데이터·PoC 검증**: 실제 XML 100건을 적재하고 ID·왕대·연도·제목을 공식 원문 5건 이상과 대조한다. 누락 기사와 지원하지 않는 XML 구조를 기록한다. 모델 10문항 결과와 실패 유형, 추론 지연·최대 VRAM을 측정한다.
2. **데이터베이스 확장**: 전체 대상 범위와 제외 자료를 정의하고 적재 건수·중복·누락을 검증한다. 출처 추적, 재적재 정책, 필요한 인덱스를 정한다.
3. **질의 계층 개선**: 스키마와 프롬프트를 정비하고 한국어 질문 평가셋을 확대한다. 현재 SELECT 검사·읽기 전용 연결·허용 함수·시간/행 제한을 검토하고, 실패·빈 결과·결과 잘림을 명확히 반환한다. 평가기는 최대 10,000행과 정렬 조건을 확인하며, 정확도는 사람이 재검토한다.
4. **Gradio 서비스 구현**: 한국어 질문 입력, 생성 SQL, 검색 결과 표, 집계 결과, 출처 및 오류 안내를 제공한다. GPU 모델을 재사용하고 우선 요청을 직렬 처리하여 메모리 사용을 측정한다. 포트·실행 명령·의존성·컨테이너 구성을 함께 문서화한다.
5. **통합·교육용 시연**: 질문→SQL→조회→화면 표시를 통합 검증한다. 지원하는 질문 예시, 검색 한계, 실행 환경과 재현 방법을 정리한다.

## 4인 역할 분담 초안

| 역할 | 주요 책임 |
| --- | --- |
| 데이터 | XML 구조·출처 확인, 파서, 적재 품질 |
| DB·질의 | 스키마, 인덱스, SQL 실행 제한, 조회 성능 |
| AI | 모델 실행 환경, 프롬프트, 평가셋, VRAM·지연 측정 |
| 웹·통합 | Gradio, 결과·오류 표시, 통합 실행, 사용자 문서 |

역할은 담당자 확정 전의 초안이며, DB 스키마·질의 반환 형식 변경은 관련 담당자가 함께 리뷰한다.

## Git·GitHub 작업 규칙

- GitHub Issue에 목적과 완료 기준을 작성하고 `feat/`, `fix/`, `docs/`, `chore/` 브랜치에서 작업한다.
- PR에는 변경 목적, 확인 방법과 결과, 남은 한계를 적고 다른 팀원 1인 이상의 리뷰를 받는 것을 기본으로 한다.
- 기본 검증은 `python -m pytest -q`다. AI·웹 변경은 해당 실행 환경의 통합 확인 결과를 추가한다.
- 실제 XML·DB·평가 결과·모델 가중치·캐시·토큰은 커밋하지 않는다. 가상 fixture만 테스트 자료로 공유한다.
- GPU 기준 환경과 모델 revision은 [실행 환경](RUNTIME.md)에 기록한다. `constraints-gpu.txt`는 관측한 의존성 버전을 제약하며 wheel 해시·이미지 digest까지 잠근 파일은 아니다.

## 분업 전 공통 기반

[데이터 검증](DATA_VALIDATION.md), [공통 인터페이스 v1](INTERFACES.md), [분업 작업 목록](TASKS.md), [실행 환경](RUNTIME.md)을 함께 확인한다. Gradio 구현 전에 `QuestionService`를 기준으로 AI·DB·웹의 연결을 유지한다.

2026-10-15 공통 기반 검증 결과:

- 실제 XML 6개를 검사하고 일반 기사 2,756건의 추출을 확인했다. 메타데이터 삭제 버그를 수정했으며 3개 왕대 300건의 검증 DB를 만들었다.
- 공식 웹과 첫 5건의 제목·왕대·날짜를 대조했다. 전체 코퍼스와 본문 전체 문자 대조는 후속 작업이다.
- 고정 어댑터 revision으로 GPU 추론·공통 서비스·10문항 평가를 실행했다. SQL 실행 10/10, 결과 일치 9/10이며 집계 오답을 기록했다.
- 기존 GPU 환경과 GPU 패키지 없는 새 CPU 환경에서 테스트 20개가 통과했다.
- CPU/GPU 빌드 stage와 의존성 제약을 구성했다. Docker CLI가 없어 새 GPU 이미지 빌드와 Dev Container 재빌드는 호스트에서 확인해야 한다.

## 커밋 점검

`git status --short`와 `git ls-files --others --exclude-standard`로 파일 목록을 확인한다. 데이터·캐시가 제외되었는지 확인한 뒤 의도한 파일을 명시적으로 stage하고 `git diff --cached`를 검토한다. 라이선스는 팀의 결정을 거쳐 추가한다.
